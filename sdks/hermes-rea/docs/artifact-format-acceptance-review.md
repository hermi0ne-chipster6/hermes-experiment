# Artifact format acceptance review

This audit uses the frozen REA `51459cf203ae1eb6b586a95b21899eaa0f631823` source. Its `ARTIFACT_FORMAT_IDS` has exactly 48 entries. That vocabulary includes container readers, native analysis targets, path/content classifications and an explicit unknown category; 48 labels do not imply 48 extraction engines or 48 operationally verified providers.

The owning sources are `src/domain/artifactGraph.ts`, `src/artifacts/artifactFormats.ts`, `src/artifacts/inventory/{classify,reader,ArtifactGraphConstruction}.ts`, `src/application/BinaryTargetResolver.ts` and `src/contracts/sessionLifecycleInputs.ts`. Source availability and fixtures alone are not runtime results. The bounded host-runtime result below is separate from fresh Workshop acceptance.

## Remaining classification and native-load lanes

| Format ID | Actual exposed operation | Minimal inert proof and acceptance boundary | Dependency or limitation |
| --- | --- | --- | --- |
| `directory` | Directory traversal, stable file hashes, virtual directory nodes, resource/application graph input | Invoke the packaged `inventoryArtifact` API with an owned resource scope against an owned app directory; require its tree, exact child hashes and directory identity. Verify the same children through MCP ZIP inventory. `open_bundle_resources` succeeds but public `inspect_artifact` explicitly refuses this resource-only session with `capability_unavailable`; a general directory is not automatically a native `open_binary` target. | Built-in `DirectoryArtifactReader`; no external engine for inventory. Directory descriptor is not an archive-extraction declaration. |
| `file` | Root/member byte identity and resource role | Put an ordinary nonmagic file in the owned resource root and assert exact bytes/hash and `file` classification. Extraction tests belong to actual enclosing readers. | No entry reader; root-only coverage does not mean a missing decoder. |
| `unknown` | Explicit uncertainty when claimed structure cannot be admitted | A truncated ELF header must remain `unknown` in inventory, with actual retained byte identity. Do not turn an unknown into a guessed raw architecture. | No entry reader. Unknown is a valid result, not successful analysis of an unknown format. |
| `elf` | Native target loading and ELF-specific parsers; inventory observes one native file | Existing compiled ELF cases already require real Ghidra/Rizin/Kuna disassembly/decompilation and static metadata. A minimal fixed ELF header may supplement classification only. | Per-operation native provider and architecture admission; the `elf` format descriptor itself has no container reader. |
| `pe` | PE/CLI inspection, native loader selection, import/resource/certificate/load-config operations | Existing .NET/PE cases prove their recorded semantic fields. A minimal PE32+ header only proves inventory classification; it must not be counted as Windows execution or full PE decompilation. | Portable static readers and suitable native providers; native Windows runtime controls remain separate. |
| `mach-o` | Thin Mach-O target/header admission and selected portable static/native-provider operations | Minimal arm64 thin header in a resource tree proves byte-based inventory only. To qualify native decompilation, use a genuine inert code-bearing Mach-O and a selected provider, then assert actual code semantics. | Thin Mach-O static analysis is not intrinsically macOS-only. No generic entry reader is provided. This new helper does not establish a complete Mach-O decompilation proof. |
| `dos-mz` | Header-selected DOS target; Ghidra import and independent native load-image verification | Authored MZ with a 32-byte header and tiny 16-bit code: require real selected Ghidra, exact target digest, all verification checks matched, source mapping and decoded MOV bytes. | Packaged Ghidra supports this lane; no DOS target execution or emulator required. Overlay/relocation coverage remains bounded to the fixture. |
| `dos-com` | Explicit caller interpretation of 1..65280 headerless bytes; Ghidra load and measured entry context | Tiny MOV/RET bytes, `format: dos-com`; assert verified load, module length, measured entry context and exact listed instruction. The same bytes in directory inventory remain `file`. | No magic-based autodetection. A `.com` suffix does not establish a COM target or runtime behavior. |
| `raw-binary` | Explicit architecture/load/entry selection, Ghidra mapping and independent source-byte comparison | Inert x86-64 XOR/RET bytes at caller-selected `0x400000`; require verified source/mapping, exact entry and instruction bytes. | Caller must supply `format`, `architecture` and `entry_point`; admitted families are x86, x86_64, arm, arm64, 6502 and m68k. One fixture does not qualify all families/endian modes. |
| `gamecube-dol` | Explicit DOL admission, PowerPC section/BSS mapping and Ghidra verification | Authored DOL with text BLR instructions, exact data and BSS ranges; select `format: gamecube-dol`, omit architecture; require verified source/load checks, text/data sections, BSS size and actual BLR decoding. | No magic and never autodetected. Ghidra adapter is required; the Hopper adapter explicitly refuses DOL. No GameCube emulation or game execution is claimed. |
| `hopper` | A retained artifact-format vocabulary entry | Audit its declaration/descriptor without inventing a database parser. The reviewed inventory classifier does not emit this label from a `.hop` member. | No `createReader`; this label alone is not operational Hopper support. |
| `analysis-database` | Target resolution routes caller-selected databases or appropriate `.hop` root paths to a database provider | A real operator-supplied Hopper database and activated compatible Hopper engine are needed to prove reopen/query behavior. A fake `.hop` inside a resource tree should remain `file`. | External licensed/provisioned provider. Linux Hopper declares database support; its macOS launch route explicitly refuses saved databases because it cannot start the required bridge. No Ghidra substitution. |
| `dmg` | Signature-based root identity; native read-only mounted entry inventory on macOS | On Linux, a `.dmg` plus valid recognized trailer/layout signature can establish only root identity and explicit unknown child coverage. Real mount/inventory needs macOS. A `koly` marker alone does not prove mountability. | `requiresDarwin: true`, `NativeDmgArtifactReader`; `extract_artifact` does not extract DMG even on macOS and directs callers to a managed read-only mount. Installing Linux disk tools does not bypass the upstream adapter contract. |
| `mach-o-universal` | Valid FAT table/slice identity; target selection and native slice entry reader are distinct paths | FAT metadata can be recognized and target resolution selects a compatible/foreign thin slice. The container inventory/extraction lane must report its macOS restriction on Ubuntu. Use independent slice metadata and byte assertions on macOS for full reader proof. | `requiresDarwin: true` for `MachOSliceArtifactReader`, which uses native `lipo`; this restriction does not mean every thin Mach-O analysis operation is unsupported on Linux. |
| `pkg` | `.pkg` plus XAR magic recognizes root identity | Require explicit unknown child coverage/refusal; do not manufacture a successful package extraction from XAR recognition. | **Upstream implementation limitation:** descriptor has no `createReader` on any host. Its absent-inventory message mentions a native macOS adapter, but no PKG reader implementation exists in this frozen source. It must not be reported as merely a missing Linux package. |

`inspect_native_load_image` explicitly distinguishes independent `verified` or `mismatch` results for DOS MZ, selected COM, raw binaries and DOL from `unsupported` independent verification for other formats. An unsupported verification result can still contain real measured provider observations; it is neither a successful byte attestation nor necessarily a native analysis failure. The helpers require `verified`, nonempty matched checks, exact source identity and a real listed instruction for the four covered lanes.

## Added helper contract and pending execution

`tests/main/launch/classification_format_cases.py` exports `CLASSIFICATION_FORMAT_CASE_IDS` and `run_classification_format_cases(mcp, work, test, package_root=None, node=None)` for the primary runner. It registers:

- `artifact-directory-classification`: packaged directory-reader API traversal plus real MCP ZIP inventory, each with ten exact member identities, including valid native headers, headerless bytes, a truncated ELF and fake Hopper member. It also asserts the public resource-only inventory refusal. Pass the exact installed package root and Node executable explicitly when available; the default resolves the standard SDK layout.
- `native-load-mz`, `native-load-com`, `native-load-raw`, `native-load-dol`: actual explicitly selected Ghidra import, independent source/load verification and instruction decoding, with source bytes unchanged and owned target closed afterward.

`classification-format-fixtures.json` stores ten inert local fixtures, exact SHA256/length, expected inventory classification and explicit native interpretation controls. The helpers use unique private test directories and never overwrite an existing fixture or execute target code. They do not install packages, start alternative providers, or access other hosts. Ghidra execution is reserved for the primary installed-Workshop validation so it cannot compete with the shared SDK build.

Fixture integrity and Python syntax have been checked. All five tests still require fresh installed-Workshop acceptance; the directory contract has additionally been exercised in the isolated host runtime as recorded below. No capability status is upgraded by adding the helper. The primary owner must integrate the test IDs and helper/data files, execute them against the corrected artifact, retain raw MCP responses and report each actual result. Any failure must be classified as a fixture assumption, package defect, upstream admission/implementation limit, external provider requirement or platform limitation before changing a status.

This is a host contract check, **not** installation or fresh Workshop acceptance of the corrected artifact.
