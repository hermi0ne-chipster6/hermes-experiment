# Cutter provider packaging and validation

Cutter is a packageable Linux dependency. It is not an external-only or incompatible-platform capability. REA's `real-cutter.yml` lists Linux, macOS and Windows, and its unchanged Python bridge supports PySide6 with a PySide2 fallback. The provider operates on a running, caller-owned Cutter session; it does not silently redirect Cutter commands to the separate Rizin provider.

The SDK packages official **Cutter 2.5.0 Linux Qt5 x86-64 AppImage**, SHA-256 `c796077954b419bd6ac36fafd0a0df36f21c8c90219dbfcfb486b34e0ad4bbc0`, extracted during the build. This avoids FUSE and privileged runtime mounts. The AppDir includes matching Rizin 0.9.1, Python 3.11, PySide2 and Qt5. Its contents and bundled notices are preserved; Cutter's GPL COPYING is retained separately with pinned source provenance.

Selection is based on actual testing. The default Qt6 artifact starts its GUI but rejects the unchanged `ReaCutterPlugin` during Shiboken conversion (`create_cutter_plugin() ... did not return an instance of CutterPlugin`), so it cannot create an REA bridge session. The same release's Qt5 artifact accepts that exact bridge and completes real operations. No upstream REA code was patched.

The `cutter` wrapper selects the bundled Python interpreter home and installs the exact bridge under `${XDG_DATA_HOME:-$HOME/.local/share}/rizin/cutter/plugins/python`. It refuses to overwrite an existing different bridge. Setup hooks initialize the managed `rea` user's plugin. `REA_CUTTER_BRIDGE_DIR`, when customized, must match between REA and Cutter. An actual X11 display is required; Xvfb supplies a disposable headless display for tests. `cutter --no-output-redirect -A 0 /absolute/fixture` opens a binary without an interactive analysis dialog.

Dependency probing found the host's missing OpenGL/EGL/GLX, SM and ICE libraries; runtime hooks install these plus Mesa software rendering and Xvfb/Xauth. The bundled Qt `xcb` platform plugin and Cutter executable both resolved their shared libraries after those dependencies were installed. No assumption of Qt's absent `offscreen` plugin is made.

Host fixture debugging passed real MCP session discovery, exact bridge hash/private ownership checks, ELF x86-64 metadata, an independently compiled `sdk_cutter_add` symbol, real add/ret instructions, unchanged input SHA-256 and session disappearance after terminating the GUI. Evidence: `/root/dev/rea-sdk/validation-logs/cutter-qt5-functional-host/results.json`. Qt6 rejection: `cutter-functional-host/cutter/cutter.stderr`. A separate direct CLI `ij` attempt occurred after its bounded GUI fixture expired and failed; it is retained as a failed attempt, not functional evidence. Installed SDK tests must pass before the capability matrix changes to functional.
