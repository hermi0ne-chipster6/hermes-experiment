# Complete SDK Maintenance CI Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Activate verified maintenance CI covering the complete declared SDK inventory.

**Architecture:** Extract monitored dependencies from repository manifests and a small explicit component policy. Query official upstream metadata without installing candidates. Run lightweight checks on hosted runners; gate manual heavy tests on a disposable KVM runner.

**Tech Stack:** Python, unittest, PyYAML, packaging, GitHub Actions, ShellCheck, Gitleaks, actionlint, SDKcraft/Spread.

**Spec:** `docs/superpowers/specs/2026-11-01-ci-design.md`

## Global Constraints

- Target SDKs/build host: Ubuntu 26.04 AMD64; hosted lightweight jobs may use Ubuntu 24.04.
- No SDK payload/pin changes, runtime activation, payments, memory migration, Store publication or automatic merging.
- Preserve AGENTS.md, Canonical skills and operator documents.
- Missing/incomplete monitoring and absent KVM cannot be reported as compatibility success.
- Existing `main` is the integration branch; nested SDK VERSION files remain unchanged.

## Review Focus

- A new external SDK part or lock file must not silently escape monitoring.
- Network errors/rate limits must remain visible and must not mean no updates.
- Mutable release tags/image digests require explicit drift reporting.
- Untrusted branches must not reach privileged build runners or credentials.
- A green hosted check is not complete integration or stable-release acceptance.
