# Complete SDK maintenance CI

Implement the operator-approved maintenance scope for all three SDKs. Keep the
existing integration repository and pinned SDK payloads; do not restructure the
publisher SDKs, update their software, or add an MCP gateway in this change.

Use GitHub-hosted jobs for behavioral tests, ShellCheck, workflow/configuration
validation, secret scanning and scheduled upstream metadata checks. Extend the
existing Python release-detector approach rather than requiring installation of
another account-level bot. The monitor writes review artifacts and job summaries;
it never edits pins, merges, publishes, spends, or upgrades a running agent.

Maintain an inventory covering primary applications, stable Hermes catalog plugin
pins, all declared Python/npm locks, container images, build/runtime tools,
Canonical Docker SDK metadata, and Ubuntu security notices for observed packages.
New external SDK parts or unclassified dependency inputs must fail coverage.
Resolve immutable candidate commits/digests where the upstream supplies them.
Report incomplete checks as errors; a newer release is a proposal, not acceptance.

Activate lightweight checks and monitoring on `main`. Keep complete SDK builds
manually dispatched on a dedicated disposable Ubuntu 26.04 AMD64 KVM runner.
Preflight runner availability on a hosted job so absence is an explicit failure,
not an indefinitely queued job or a compatibility pass. Retain build artifacts,
checksums, per-job evidence and platform package inventories. Full application
integration acceptance remains separate from smoke success and stable promotion.

Use read-only workflow permissions, pinned third-party tools/actions, bounded job
timeouts and concurrency. Do not provide Store or production credentials. Preserve
the original charter, AGENTS.md and the three installed Canonical skills.
