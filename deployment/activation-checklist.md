# Operator activation

These examples are disabled intentionally. SDK readiness proves packaging; it does not authorize an unattended run. Consult the verification report for checks actually completed.

1. Use three separate project directories (`/srv/hermes/a`, `/srv/hermes/b`, `/srv/hermes/c`), Ubuntu 26.04 AMD64, and the reviewed SDK revisions. List Canonical `docker-ce` before `hermes-execution` in B. Never share a writable `/project`, Docker socket, Hermes home, mailbox credentials, or wallet keys between roles.
2. Populate each SDK's `configuration` mount from a separate operator-owned directory. It is read-only inside the Workshop and survives refresh. Copy the applicable `.example` files, review them, and remove their suffix. Use mode 0644 for operator seed files. A imports the seed into its writable profile at `/home/workshop/.hermes/config.yaml`. Later edits belong in that profile. When migrating the legacy symlink, A preserves its original bytes in `config.yaml.pre-sdk-migration`. In A include the supplied **verbatim original** `original-charter.md.example`; its SHA-256 must be `fab40f6dc5d2416db23e43d83de97c3b59db52c3d2e7bf01c051a7d9bbefd897`. Setup links it to native `/project/.hermes.md`; operational launches require that context and refuse a different charter. The operator document is outside SDK payloads. Upstream SOUL.md remains unchanged, and the unapproved revised charter is excluded. Charter resource descriptions do not provision accounts, fund a treasury or finish a wallet; actual delegated capabilities follow the approved runtime configuration.
3. Install the host diary modules under `/opt/hermes-experiment/diary` with operator ownership. Create the dedicated `hermes-journal` system identity, install both supplied units, and enable them only after reviewing their paths. Give the host Workshop daemon's operator identity access to the runtime directory and `agent.sock` through the writer's service group or a persistent ACL; give it no database-directory or control-socket access. Only `agent.sock` may be tunneled into A. **Never forward `control.sock`**: a privileged tunnel proxy cannot identify the agent's original UID. The database and backup directory must never be mounted into A/B/C.
4. Select a model provider and connect the secret plugs through Workshop. `model-key` is mapped to the provider variable named by `HERMES_PROVIDER_KEY_ENV`; do not put values in the YAML, this document, a shell command argument, a writable mount, or build logs. A's `sandbox-api-key` and B's `api-key` must identify the same dedicated API credential. Any process in a Workshop can request that Workshop's connected secrets.
5. Provision A's dedicated REA SSH key through `rea-ssh-key`, C's public-key allowlist in the configuration mount, and A's pinned `rea_known_hosts`. Launch or an SDK-changing refresh imports that fixed public file into `/etc/ssh/hermes-rea/authorized_keys` with root ownership for OpenSSH StrictModes. When only this configuration file changes, `workshop refresh` can report no updates; explicitly reapply the packaged hook as the operator: `workshop exec --uid 0 c -- env SDK=/var/lib/workshop/sdk/hermes-rea bash /var/lib/workshop/sdk/hermes-rea/sdk/hooks/setup-project`. This also applies key revocation. Verify a real MCP initialize/tools-list exchange, strict host-key rejection, forced command, no PTY/forwarding, process cancellation, and analysis of a synthetic binary. No private key goes to C.
6. Configure Hindsight using its native setup wizard and explicitly select `local_embedded` for the included runtime, extraction model/provider and credentials. Its default mode is cloud; `memory.provider: hindsight` alone does not select the embedded backend. The native embed manager starts the packaged API on demand and stops it after inactivity, so do not add a duplicate daemon. Confirm retention and recall across separate CLI heartbeats and a restart. Its API is packaged in an isolated environment; the pinned pg0 0.15.2 wheel bundles PostgreSQL and pgvector, and its offline startup still needs a real isolated test. Existing bank backups remain untouched. Restoring a backup is a separate operator action, with the same embedding model/dimensions and a tested rollback. MemPalace remains a synthetic evaluation candidate, with Hindsight the baseline.
7. Verify native interactive execution in A and explicit remote routing to B and C. Check the OpenSandbox MCP allowlist against the operations planned for B. Verify that B or C connection failures return errors to the caller. Review the existing Buzz, email and cron toolsets separately. Native Hermes cron scripts run in A under `HERMES_HOME/scripts`. Keep A and B script directories separate.
8. Configure the dedicated mailbox's SMTP/IMAP, `EMAIL_ADDRESS`, authenticated sender checks and allowlist. Email From alone is insufficient. Configure native Buzz with a dedicated Nostr identity and authenticated operator public keys. The opt-in `send_agent_email` tool uses the native email sender with one plain recipient; it cannot choose a From identity or attach files. `notify_operator` has a fixed operator destination. Enable each native adapter only after send/receive/approval-response checks. Keep ACP adapters disabled. Then enable the gateway marker and restart the user service after connecting secrets.
9. Establish Cloudflare's delegated subdomain boundary first. Use a dedicated tunnel credential in B; standard DNS API tokens are zone-scoped, not restricted to one arbitrary subdomain. Preconfigure wildcard DNS/tunnel routes or true delegation. Expose only the chosen workload service, never OpenSandbox, REA, SSH, Docker or diary control surfaces. The included cloudflared unit does not create DNS records or ingress policies.
10. Preserve Stripe Link CLI policy decisions and Sui's **2-of-3 multisignature**. Link uses its native `--mcp` mode; its empty tool allowlist must remain disabled until transaction-policy checks pass. Native Link identity state and `LINK_AUTH_FILE` live under `.link-cli`; no login or wallet setup is performed by installation. This deliverable does not create or finish the wallet, migrate identities, authorize transactions, or invent a replacement Stripe policy engine. A gateway response is never sufficient spending authority.
11. Validate bridge ACLs and refresh persistence, then gateway/heartbeat concurrency and recovery. Set the fixed non-root Workshop owner in `enter-heartbeat` (example: `admin`) and its actual project path. The root host runner retains private diary access but enters Workshop through that owner's client identity. Install the operator-owned two-hour cron entry only after the diary receipt path and actual CLI hook execution pass. Native Hermes cron remains available; the operator heartbeat rule is separate. A successful process exit without a matching diary receipt is incomplete.
12. Test release candidates and promote exact tested artifact hashes under operator review. Refresh downloads the promoted SDK revision; it never calls `hermes update` at runtime. Credentials, DNS, Store/CI publication and production activation were not performed by generation.
